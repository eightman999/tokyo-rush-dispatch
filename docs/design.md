# 実装設計

## 画面

路線ごとの色を保持した暗色の指令卓。操作の主役は路線網と在線列車とする。
配色は深い青灰 `#101922`、パネル `#14212c`、境界 `#2a3b48`、指令の橙 `#f4a15a`、
平常 `#78c6a1`、重大遅延 `#f1847b`。日本語はNoto Sans JP、時刻・列車番号はBarlow Condensed。

```text
識別・ガイド・記録
シナリオ / シード / 指令時刻 / 再生操作
スコア / 遅延 / 最大遅延 / 待機旅客 / 旅客損失
路線選択    路線網                      指令卓
障害情報    計画・実績スジ図            対象 / コマンド / 駅
駅状態      列車一覧                    運行ログ
```

スマートフォンでは路線一覧を横スクロール、パネルを縦配置とする。
定刻・遅延の違いは色だけでなく数値、警告記号、状態テキストでも表す。

## ファイルと責務

| ファイル         | 責務                                                    |
| ---------------- | ------------------------------------------------------- |
| `src/network.js` | 駅、路線、接続、シナリオ、指令説明                      |
| `src/engine.js`  | 1秒刻みの離散シミュレーション、指令検証、損失、記録再生 |
| `src/main.js`    | SVG路線図、スジ図、指令卓、ファイル書出・読込           |
| `src/style.css`  | レスポンシブ指令卓と状態表現                            |

シミュレーション時刻は07:30を0秒とする。初期状態はダイヤを負の時刻からウォームアップして生成。
通常列車の状態は `pending → dwelling → running/blocked → dwelling → done`。
直通制約はシーケンス番号が同じ列車の境界駅の実出発を参照する。
出発条件は実到着＋停車、計画出発、直前の実出発＋120秒、接続先の実出発＋35秒、指令延発、障害終了時刻の最大値。
待避駅のみ同一方向2列車のホーム占有を許し、快速優先時に普通列車を快速の出発＋ヘッドウェイまで待機させる。

乱数は32bitのシード付き生成器を固定ステップで消費する。ブラウザの描画頻度・再生速度は計算結果に影響しない。
指令の検証を状態変更より前に行い、不正指令は状態・ログ・スコアを変更しない。
JSON記録はバージョン、時刻、シード、シナリオ、指令件数と各指令の妥当性を検証してから再現する。
